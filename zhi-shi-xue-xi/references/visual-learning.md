# 可视化制作与核对

主技能识别到复杂逻辑关系时，主动制作图解或演示，不等用户提醒。依据具体理解障碍选择形式，遵守用户的语言和交付限制。

## 图解

- 步骤用流程图，对象及模块关系用关系图，层级用结构图，概念差异用对照表，数值随时间变化用曲线。
- 简单静态关系可用 Mermaid；科学图表或需要导出分享的数值图，用标准绘图工具生成独立文件。选择环境能够显示的形式。
- 控制节点数量，围绕当前学习目标保留必要关系。复杂项目先总览，再单独展示当前路径；用户要求完整地图时，以可导航、可分层的方式覆盖范围。
- 箭头注明调用、传递数据、先后或因果。不要混淆因果与相关，不用节点大小或装饰暗示不存在的定量关系。
- 与源码使用同一组模块、函数和数据名称。教学简化时标注省略的关键部分，不将简化图冒充完整架构。
- 图中文字清晰；数值图标出坐标、单位和参数，不能仅靠颜色区分内容。图下说明起点、阅读顺序和关键结论。

## 交互演示

- 围绕一个学习目标，例如逐步查看函数执行，或改变参数观察结果。避免无关功能；不要自行把教学扩展成产品开发。
- 控件用中文名称和单位，默认值有代表性。变化后及时更新图形、结果和必要解释，让用户知道自己的操作引起了什么变化。
- 代码执行演示显示当前步骤、关键变量及输出，明确它是源码实际执行、模拟执行还是教学简化。模拟应遵循所展示代码的逻辑。
- 图形与结果共用同一套计算逻辑。处理空值、零值和越界输入；显示可以四舍五入，计算保留精度。控件支持键盘操作，图旁保留可读的关键结果。
- 用户要求可下载 HTML 时，生成完整可直接打开的文件，优先内嵌资源；否则可以使用环境支持的即时交互预览。静态截图不称为交互演示。
- 交付前检查默认参数和有代表性的边界，操作至少一个控件验证联动。能用浏览器时检查界面；不能实际运行时，明确说明尚未验证的部分。

## 数字与事实

核对单位、百分比转换、公式和时间范围，区分模型假设与现实结论。文字、图、公式和交互结果必须一致。

演示依赖的假设要让初学者看得见，例如计息周期、是否追加本金、是否忽略税费。不要从简化教学模型推出没有证据支持的现实预测。

有生成文件时提供可打开的文件链接及最短使用说明。视频仅在用户明确要求时处理；工具只能生成脚本或分镜时，准确说明交付范围。
